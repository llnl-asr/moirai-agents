# Lessons: tools_moirai_venv

- [L-3927f4e2] dftracer[modules] and dftracer-compose in the mammoth moirai venv (user: "install the prerelease of dftracer with pip install --pre dftracer[modules] and then run dftracer-compose to link all required features"): the already installed post55 has no `modules` extra, `pip install --pre --upgrade 'dftracer[modules]'` gives dftracer 2.2.0.post57.dev0 + dftracer-modules (a newer wheel, in the same venv the repaired single-core layout survives: one libdftracer_core.so.4.3.0, moirai wheel and pydftracer common.py still current). dftracer-compose needs cmake >= 3.24 (system 3.23.1 fails): pip install cmake ninja into the venv and run it with PATH=<venv>/bin:$PATH; --check first, then plain; on mammoth it links mpi-mvapich-2.3, hdf5-1.10-serial, papi-5.6, hwloc-2 (hip and cuda absent). Side effect: the core then pulls system libhwloc and libmpi (intel-classic mvapich runtime), and `import dftracer.dftracer` fails under the anaconda python with "GLIBCXX_3.4.30 not found (required by .../anaconda3-2024.06/lib/libicuuc.so.73)", pydftracer prints "DFTracer was enabled but not available" and the decorators log 0 events. Fix: LD_PRELOAD=/collab/usr/gapps/python/toss_4_x86_64_ib/anaconda3-2024.06/lib/libstdc++.so.6 for the python, moirai-service start and stop: then 3 of 3 TEST events (verified with tools/verify/t3.py, ring name /moirai_<x>, not /dev/shm/...). moirai_env.sh of the integrate stage must export it; a mpi variant can also be left out with dftracer-compose --disable mpi,hwloc if the preload is unwanted.

- [L-2399c610] Decorator test through moirai-service: MOIRAI_SERVICE_SHM must be a POSIX shm name (/moirai_<x>), not a /dev/shm path (with a path the events spill and no TEST event reaches the trace), and the service takes a verb: `moirai-service start` / `moirai-service stop` (no verb prints usage, exit 2). pkill -f moirai-service inside a command line that contains the string kills that shell (exit 144): keep the pid or use the stop verb.
