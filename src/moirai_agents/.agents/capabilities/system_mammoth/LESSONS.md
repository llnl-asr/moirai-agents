A wrong token earlier produced "Login Succeeded" yet denied pulls: the cause was the token, so re-login overwrites it. Give the user the path and the login command, and never ask them to paste the token in chat.

- [L-7a370b5f] When giving a user a podman login command, do not pipe a variable ($T from read -rs) into --password-stdin: if the variable is not set in that shell (a different shell, such as mammoth35 vs mammoth34) podman reads an empty password and fails with "reading password: inappropriate ioctl for device" and "No credentials ... found in auth.json". Give the interactive form (podman login <registry> -u <user> --authfile <file>, paste the token at the Password prompt) and then a check that prints only the hosts of auths in the file.
