- [L-5bc710bd] When the user does not know the test command ("figure that out based on the repo"), clone the repo into workspaces/<app>-peek/src and read README, nextflow.config, conf/test.config and assets. lc.llnl.gov https clone asks for credentials and fails in the agent; the SSH form that worked is ssh://git@czgitlab.llnl.gov:7999/<group>/<repo>.git (lc.llnl.gov:7999 refuses). pipeline_new defaults ref to main: a repo whose branch is master gives session_error "no session for <url>" and leaves a session-less pipeline; call pipeline_new again with ref='master' (a second pipeline id is created, say which one is live).

- [L-a054e6a3] Blank draft chat with a git URL but no test command: pipeline_status without a pipeline argument returns every pipeline (59 KB, saved to a file), so grep the file for the draft id and read only its head. Then ask_user for the missing small test command before pipeline_new(kind='run').

- [L-5ac98f1b] Re-running a stage validator for a "prove everything" recheck (smoke_validate) reset the stage's approval: the next pipeline_advance of the following stage failed with "stage discover cannot start before: smoke (needs_user)". Fix that worked: pipeline_decide for the earlier stage with the user's original words and a note that the validator was rerun on the same job, pipeline_advance it, then plan_update the later stage when its advance says the plan is out of date. Prefer reading validators' recorded verdicts over re-running them when only proof is wanted. Also: an applied capability proposal can be applied by the user in the panel without telling the agent; probe the tool (discover_scan returned 22 files, 128 hits) before asking again.

- [L-57892bb9] When the user says "prove everything", re-run the checks instead of quoting earlier output: sacct for the job, `nextflow log <run> -f name,status,exit` counted by status, the outputs per folder (find | wc -l), id -Gn plus a read test of every database path, skopeo list-tags with the session auth file, the venv import and versions, and the stage validators (smoke_validate passed, discover_validate still failing touch_points until the scanner proposal is applied); then list what could not be proven. Taxteller recheck found one wrong earlier number: seqscreen wrote 126 files in total (about 63 per mate), not "about 100 per mate" as the discover agent said, and explore_validate could not be rerun because the moirai MCP tool list had changed.

- [L-27774d75] When the user asks "what is going on." while a gate or a capability proposal waits on them, answer with a stage table (passed / waiting / not started), the exact decisions needed (proposal id and the gate questions) and the run state (jobs, access), in about ten lines; offer to repost the gate as one short message in case it is not visible in the UI. A long autonomous run of tool calls with no user-facing text is what prompted the question.

- [L-fd6abd5a] Closing a stage whose validator needed a new capability argument: after capability_apply, rerun the validator (smoke_validate with slurm_job_id and data_dir passed), then pipeline_advance can still refuse with "the plan is out of date (validator failed: ran)": plan_update with why (what ran and how it was validated) clears it, then advance works. Taxteller smoke advanced to discover this way.

- [L-bd7ffa7a] "ok is smoke is done, continue with the pipeline" approves the stage but not a capability change: a staged capability proposal (here app_smoke ded8109f29de) needs its own explicit yes (ask_user or the Capabilities panel) before capability_apply, even when the stage cannot advance without it.
