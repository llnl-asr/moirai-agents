# Lessons: prov_annotate

- [L-47cab606] A shell step of a Maestro YAML (AlphaFold 3, Rosetta) is annotated with mode yaml_step, not by editing the app: the wrapper is an EXIT trap at the top of the step's cmd that calls the root _moirai_prov.py as a script with the moirai venv's Python (MOIRAI_PYTHON, else beside MOIRAI_SERVICE or moirai-service on PATH, resolved before the step activates its own venv). Tie each record to what the step really did with a shell variable the cmd sets (uri "${PDB_FILE}") rather than a fixed path, so an early `exit 0` (peptide_prepack skip when PEP_ID is "-") records nothing; give both sides of a hop the same type and key text (case id $(TARGET)/$(PEP_ID)/seed-$(SEED)_sample-$(SAMPLE)).

- [L-a532f2d2] maestro_dry in annotate_validate is inconclusive, never a failure, when `maestro run --dry` fails on the SOURCE YAML too (a parameter generator such as biotox's gen.py is needed). Pass maestro=<session>/tmp/biotox-env/bin/maestro and maestro_args="--pgen gen.py --pargs inputs:<path> --pargs dock_mode:all --pargs dock_chains:Z --pargs seeds_per_chunk:1" (the arguments of run-biotox.sh) so the dry run can pass; an inconclusive check blocks pipeline_advance.

- [L-8f5af9d7] dftracer_service (moirai-service) is a singleton per trace prefix (MOIRAI_LOG_FILE) per host: a second `start` for the same prefix is refused with 'dftracer_service is already running on <host> (PID ..) for <prefix> — refusing to start a second instance. Run `stop` first', and `stop` from any step stops the one that is running. So in a one-node Maestro study the yaml_step block's own service start is refused (its helper then spills because the step ring it exports does not exist) and its EXIT-trap `stop` kills the conductor's service; every later step's Python hook finds 'no dftracer_service is accepting events on <conductor ring>' and spills. Services that do start write the same prov_<host>.pfw.gz name and overwrite each other. Fix design: in a step block, if the inherited MOIRAI_SERVICE_SHM ring already exists in /dev/shm on this node, reuse it and neither start nor stop; only on a node without it start an own service with a unique ring AND a unique MOIRAI_LOG_FILE prefix (…-step-<id>), and stop only a service the block started. Steps with no yaml_step activity (prepack, analyze) then work through the conductor's ring.
