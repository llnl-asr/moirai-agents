Seeds are not a flag: the AF3 seeds are the modelSeeds of the chosen input JSON (trypsin [5], Nav1_2_KIIIA [1,5]); the tunables are seeds_per_chunk and num_samples of gen.py. live_inputs_detect finds only argparse flags of the per-case helper scripts and PEP_* names, so curation comes from the real launch (baseline launch.sh maestro line, gen.py, or the package scripts), not from the detector. PEP_NSTRUCT and PEP_RADIUS are YAML env-block variables: gen.py --pargs pep_nstruct/pep_radius only change the recorded run_config entity, the real write into the run copy of biotox.yaml is done by biotox_run_script (or make_run in the package). A command template must only use settings the launch it wraps really takes, so read the launch's scripts first and report ineffective wanted inputs as a builder change, not as dead slots. Progression of what the launch honours: the first published package's run_all.sh (env overrides SCALE, QUEUE, INPUT_JSON, DOCK_MODE, DOCK_CHAINS_<scale>, SEEDS_PER_CHUNK, NUM_SAMPLES, PEP_NSTRUCT, MINUTES at most 120, STEP_MINUTES; REUSE_VENV=1) did NOT take PEP_RADIUS, nodes (fixed to 1) or a longer time limit; the biotox-v2 package (PEP_RADIUS via make_run --pep-radius, NODES_baseline, MINUTES_baseline) does, with nodes above 1 or minutes above 120 needing the user's own approval text (APPROVED_NODES / APPROVED_OVER_120), never invented. A plain `flux batch --wrap maestro run` template lacks the real launch.sh preamble (python/3.12 module, moirai env, ld_clean, conductor service), so a faithful live run calls a generator (biotox_run_script) or the package launch. After live_inputs_write, call live_inputs_render and compare the slots to what was written: one stored spec was found replaced (6 inputs, different command) without a later write.
